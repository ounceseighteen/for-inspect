# Мир Кино — сервис бронирования и продажи билетов в кинотеатр

Веб-приложение на Flask + SQLite: афиша, выбор мест, бронирование и оплата
билетов, программа лояльности, касса и админ-панель.

## Возможности

**Клиент**
- Афиша, поиск и фильтрация фильмов, карточка фильма с сеансами.
- Интерактивный выбор мест на схеме зала, бронирование и оплата
  (банковской картой или бонусами).
- Электронный билет с кодом (например `Д1-12`) и QR-кодом для входа — на почту.
- Личный кабинет: история билетов, смена имени/пароля, статусы «забронирован /
  оплачен / посещён», возврат оплаченного билета (не позднее чем за 6 часов
  до сеанса, бонусы возвращаются на карту).
- Смена email в личном кабинете — только после подтверждения кодом на новый
  адрес; на старую почту уходит уведомление об изменении.
- Избранное «Хочу посмотреть» с отдельной вкладкой в личном кабинете.
- Программа лояльности: бонусная карта, уровни Basic/Silver/Gold/Platinum,
  кешбэк 3–15 %, история операций.

**Кассир**
- Продажа билетов с кассы по email клиента: схема зала, акции, оплата.
- Поиск в журнале броней (по коду билета / имени / email), фильтр по статусу.
- Подтверждение оплаты брони, пополнение бонусных карт клиентов.

**Админ**
- Панель: цифры, график продаж за 14 дней, выручка за неделю, топ фильмов,
  посещаемость на 7 дней вперёд, топ фильмов по рейтингу зрителей и
  последние отзывы.
- Управление фильмами (включая загрузку постеров), залами (создание мест,
  закрытие зала отменяет предстоящие сеансы), сеансами, акциями.
- Управление пользователями: роли, блокировка.
- Журнал действий (аудит): входы/выходы, продажи, подтверждения оплаты.

## Запуск

```bash
# 1. Войти в окружение и поставить зависимости
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt

# 2. Настроить окружение
copy .env.example .env          # Windows
# заполнить SECRET_KEY, MAIL_USERNAME, MAIL_PASSWORD, ADMIN_EMAIL, ADMIN_PASSWORD

# 3. Запустить (БД создастся автоматически при первом старте)
python main.py
```

Приложение будет доступно на http://127.0.0.1:5000

Для презентации/разработки добавьте в `.env`:

```
SEED_DEMO_DATA=1
DEMO_PASSWORD=DemoPass123!
```

Эти строки уже есть в приложенном `.env` — при первом запуске с чистой базой
создадутся демо-данные (см. ниже). **Важно:** демо-контент создаётся только
при первом запуске и только если в таблице `users` ещё нет ни одного
пользователя. Если база уже существует, просто удалите файл `mirkino.db`
и запустите приложение заново.

## Настройка

### Переменные окружения

Берутся из `.env` (см. `.env.example`).

| Переменная                | Обязательно | Описание |
|---------------------------|:-----------:|----------|
| `SECRET_KEY`              | да          | Ключ сессий. Сгенерируйте: `python -c "import secrets; print(secrets.token_hex(32))"` |
| `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_SERVER`, `MAIL_PORT` | да | SMTP для отправки кодов и билетов (для РФ — Яндекс/Почта Mail.ru, не Gmail, см. ниже) |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | да | Учётка администратора при первом запуске |
| `SEED_DEMO_DATA`          | нет         | `1` — создать демо-аккаунты и контент |
| `DEMO_PASSWORD`           | нет         | Общий пароль демо-пользователей (по умолчанию `DemoPass123!`) |
| `FLASK_DEBUG`             | нет         | `1` — режим отладки. **Только локально, см. ниже** |
| `FLASK_HOST`, `FLASK_PORT`| нет         | Адрес и порт прослушивания (по умолчанию `127.0.0.1:5000`) |
| `REFUND_HOURS_BEFORE`     | нет         | За сколько часов до сеанса ещё можно вернуть билет (по умолчанию 6) |
| `FORCE_HTTPS`             | нет         | `1` — Secure-флаг на cookie (только под HTTPS) |
| `DB_PATH`                 | нет         | Путь к файлу БД (по умолчанию `mirkino.db`) |
| `RATE_LIMIT_STORAGE_URI`  | нет         | Хранилище счётчиков лимитов (по умолчанию `memory://`) |

### Почта (коды подтверждения и билеты)

Регистрация, восстановление пароля, выпуск карты и **смена email в личном
кабинете** подтверждаются кодом из письма; оплаченные билеты приходят на
почту с QR-кодом.

**Важно про Gmail:** `smtp.gmail.com:587` с российских IP молча обрывает
соединение до аутентификации — письма не отправляются вообще (ни билеты,
ни коды). В `.env` по умолчанию настроена **Яндекс Почта** (`smtp.yandex.ru:465`).
Нужно заполнить `MAIL_USERNAME` (адрес ящика) и `MAIL_PASSWORD` (пароль
**приложения**, не обычный): https://id.yandex.ru/security/app-passwords

Альтернативы: `smtp.mail.ru:465` (пароль приложения на id.mail.ru) или любой
другой SMTP. Флаги `MAIL_USE_TLS` / `MAIL_USE_SSL` выбираются автоматически
по порту (587 → TLS, 465 → SSL), при желании задаются в `.env` явно.

Если письма не нужны (например, демонстрация без почты) — регистрация новых
клиентов будет недоступна, но готовые демо-аккаунты из раздела выше дают
полный доступ ко всем функциям.

### Хранилище лимитов

Поначалу приложение показывает предупреждение flask-limiter про in-memory
storage. Это ожидаемо: по умолчанию счётчики лимитов живут в памяти одного
процесса. Для продакшена поставьте Redis и укажите в `.env`:

```
RATE_LIMIT_STORAGE_URI=redis://localhost:6379/0
```

Без Redis можно использовать файловое хранилище: `filesystem://./rate_limits`.

## Безопасность

### Зачем убран `debug=True`

`app.run(debug=True)` включает интерактивный дебаггер Werkzeug: прямо из
браузера открывается консоль на `/<Werkzeug console>` и `/console`, через
которую выполняется произвольный код на сервере (фактически полный захват
системы). Для запуска достаточно узнать/подобрать `SECRET_KEY` (или PIN,
печатающийся в консоль запуска). Поэтому:

- `debug` теперь управляется только через `FLASK_DEBUG=1` в `.env`,
  по умолчанию выключен;
- сервер по умолчанию слушает `127.0.0.1`, а не все интерфейсы, — чтобы
  даже в debug приложение не торчало наружу по сети;
- интерактивный дебаггер отключён **жёстко и безусловно**:
  `app.run(debug=False, use_debugger=False, use_reloader=config.DEBUG)`.
  `FLASK_DEBUG=1` теперь включает только авто-перезапуск при правке кода,
  но `/console` не регистрируется вообще. Это закрывает случай, когда
  приложение стоит за обратным прокси и «внутренний» `127.0.0.1` фактически
  доступен снаружи — от одной проверки `FLASK_HOST` такая конфигурация не
  защищала;
- на проде debug-режим включать нельзя.

### Секреты и `.env`

`SECRET_KEY` подписывает cookie сессии: кто его знает — подделает сессию
любого пользователя, включая админа. `MAIL_PASSWORD` даёт доступ к ящику,
с которого уходят билеты и коды. Поэтому:

- секреты лежат **только** в `.env`, в коде и в `config.py` их значений нет
  (в репозитории — только `.env.example` с пустыми значениями);
- `config.py` проверяет `SECRET_KEY` при старте: обязателен, не короче
  32 символов, не из списка базовых значений — приложение не запустится
  со слабым ключом;
- в корне проекта лежит `.gitignore`, который исключает `.env`, `*.db`
  (хэши паролей и данные клиентов), бэкапы, логи, `__pycache__` и `.venv`.
  Без него `.env` мог попасть в репозиторий вместе с ключом и паролем почты.

### Что ещё закрыто

- CSRF-защита всех форм и fetch-запросов (Flask-WTF, токен в каждой форме).
- Пароли — хэш scrypt (werkzeug), старые sha256-хэши переходят на него
  автоматически при входе.
- Подтверждение почты кодом: сам код хранится только в виде хэша, 6 попыток,
  5 минут жизни, восстановление пароля невозможно без подтверждения кода.
- Защита от перебора логина/восстановления/кодов — ограничения
  flask-limiter.
- Загружаемые картинки проверяются Pillow (только реальные изображения,
  расширения из белого списка), чтобы нельзя было подсунуть HTML/SVG с
  скриптом.
- Бронирование мест защищено уникальным индексом `(session_id, seat_id)`
  — двойная продажа одного места невозможна даже при параллельных запросах.
- Куки: HttpOnly, SameSite=Lax, Secure под HTTPS.
- Security-заголовки на всех ответах: `X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`, Content-Security-Policy.
- Журнал действий для аудита (вход/выход, продажа, подтверждение оплаты).
- Самостоятельное «пополнение» бонусной карты клиентом отключено — только
  через кассу (это была дыра «бесплатные бонусы = бесплатные билеты»).
